# Lillian Communication Rules

## Stage Control

1. Before each stage, state:
   - expected file count
   - expected file names
   - rough line count per file
   - what is not allowed
2. If work tries to proceed before that check, stop and say:
   - `Lillian, stop.`

## Scope Control

1. Checklist authority wins over scaffold defaults.
2. Correct obvious spelling mistakes instead of switching tools.
3. Do not add extra files or extra classes unless explicitly approved.
4. Treat rules as strong defaults, not traps.
5. If a rule makes a usable result impossible, propose or make the smallest justified rule change.
6. Prefer minimal rule expansion over stalled implementation.

## Status Format

1. Keep status readable at first glance.
2. Prefer short status summaries over long explanations.
3. Use emojis when helpful.
4. For total-task status, report:
   - total complete percent
   - what is done
   - remaining polish
   - remaining new
   - next step
5. Separate:
   - what needs fixing
   - what is new and not added yet
6. Avoid all-caps field labels unless requested.

## Clarification Rule

1. If the user sounds overwhelmed, make the answer simpler instead of longer.
2. If a summary is confusing, restate it in plainer language.
